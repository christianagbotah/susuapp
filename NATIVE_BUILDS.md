# Native Builds — Android, iOS & Desktop

iSusuPro ships as a **server-dependent PWA**: the Next.js server (API routes), the NestJS backend (`mini-services/isusu-api`) and Prisma must run on a host. The native apps are therefore **thin WebView shells that load the live deployment** — not offline static bundles.

```
┌─────────────────────┐        loads         ┌──────────────────────────┐
│  Android / iOS      │ ───────────────────▶ │  Hosted iSusuPro server  │
│  (Capacitor 8)      │   server.url         │  Next.js + NestJS + DB   │
├─────────────────────┤                      └──────────────────────────┘
│  Windows / macOS /  │ ───────────────────▶
│  Linux (Tauri 2)    │   dist/index.html
└─────────────────────┘   → redirect to server
```

- **Mobile** — Capacitor 8 (`android/` + `ios/` projects committed; iOS uses Swift Package Manager, no CocoaPods needed)
- **Desktop** — Tauri 2 (`src-tauri/` Rust shell, tray + close-to-tray; macOS ships as a Universal binary — one DMG for Intel & Apple Silicon)
- **Bootstrap shell** — `dist/` (generated by `bun run shell:build`): branded splash that probes the server, redirects when online, shows a branded offline screen otherwise.

## 1. Configure the server URL

Every native build targets ONE deployment. Set it at build time:

```bash
APP_SERVER_URL=https://your-deployment.com bun run cap:sync:android   # Android
APP_SERVER_URL=https://your-deployment.com bun run shell:build        # Desktop (before tauri build)
```

Defaults to `https://isusupro.com` if unset (see `capacitor.config.ts` and `scripts/build-native-shell.mjs`).

> **Local dev on the Android emulator:** the emulator reaches your machine via `10.0.2.2` —
> `APP_SERVER_URL=http://10.0.2.2:3000 bun run cap:sync:android` (cleartext is enabled automatically for `http://`).

## 2. Android

### Build via GitHub Actions (recommended — no local SDK needed)
Push a tag (`git tag v0.3.0 && git push --tags`) or run the workflow manually:
**Actions → "Build Android App" → Run workflow** (optionally set the server URL).

Artifacts: `iSusuPro-debug.apk` (debug-signed, sideload-ready) and `iSusuPro-release-unsigned.aab` (sign with your Play Store key before upload).

### Build locally
Requires Android Studio (SDK 36, Java 21):

```bash
bun install
APP_SERVER_URL=https://your-deployment.com bun run cap:sync:android
bun run android:brand        # re-apply brand splash/launcher after a re-sync
bunx cap open android        # Android Studio → Build > Build Bundle(s)/APK(s)
```

### Play Store release
1. Generate an upload keystore: `keytool -genkey -v -keystore isusupro-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias isusupro`
2. Add to `android/gradle.properties` (never commit):
   ```
   ISUSUPRO_UPLOAD_STORE_FILE=/absolute/path/isusupro-upload.jks
   ISUSUPRO_UPLOAD_KEY_ALIAS=isusupro
   ISUSUPRO_UPLOAD_STORE_PASSWORD=…
   ISUSUPRO_UPLOAD_KEY_PASSWORD=…
   ```
3. Wire a `signingConfigs.release` block in `android/app/build.gradle`, then `./gradlew bundleRelease`.

### Push notifications (FCM)
Add `google-services.json` to `android/app/` and the `com.google.gms:google-services` Gradle plugin to enable `@capacitor/push-notifications`.

## 3. iOS

The `ios/` Xcode project is committed (scaffolded with Capacitor 8 / SPM — plugins resolve through `ios/App/CapApp-SPM/Package.swift`, so **no CocoaPods install** is needed). Branded assets live in the repo: App Store icon (1024×1024, no alpha), 2732×2732 launch splash, emerald launch screen, and `Info.plist` permission strings (camera for Ghana Card OCR, photo library, location for agent routes, Face ID).

### Build via GitHub Actions (recommended — no Mac needed)
**Actions → "Build Mobile Apps" → Run workflow** (same workflow as Android). The `ios` job runs on `macos-latest`, archives with Xcode and produces **`iSusuPro-ios-unsigned.ipa`** — install it on your iPhone via [Sideloadly](https://sideloadly.io/) / AltStore, or re-sign with your certificates.

### Build locally (Mac with Xcode 16+)
```bash
bun install
APP_SERVER_URL=https://your-deployment.com bun run cap:sync:ios
bun run ios:brand          # re-apply brand icon/splash/Info.plist after a re-sync
bunx cap open ios           # Xcode → select your team → Archive
```

### App Store release
1. Apple Developer Program membership + an App ID with Push Notifications enabled (bundle id `com.isusupro.ghana`).
2. In Xcode: select your signing team, then Product → Archive → Distribute App → App Store Connect.
3. Attach the privacy policy URL and demo reviewer credentials in App Store Connect.
4. Push notifications need an APNs auth key uploaded to your push provider (FCM → APNs for iOS devices).

Signing on CI (optional): add `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD` and provisioning secrets, then switch the archive step to signed `xcodebuild ... -exportArchive`.

## 4. Desktop (Windows / macOS / Linux)

### Build via GitHub Actions (recommended)
**Actions → "Build Desktop Apps" → Run workflow.** Builds on all three OSes in a matrix and produces:
- Windows: `.msi` + `.exe` (NSIS)
- macOS: Universal `.dmg` (Intel + Apple Silicon — one installer for every Mac)
- Linux: `.AppImage` + `.deb`

Tag builds (`v*`) also create a draft GitHub Release with the installers attached.

### Build locally
Requires Rust (`rustup`) + platform deps (Linux: `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev`):

```bash
bun install
APP_SERVER_URL=https://your-deployment.com bun run shell:build
bunx tauri build            # or: bun run tauri:build:windows / :macos / :linux
```

Desktop behaviour (implemented in `src-tauri/src/lib.rs`):
- **System tray** with Show/Quit menu; left-click reopens the window
- **Close-to-tray** — closing the window hides it (sessions stay warm); Quit via tray

### Dev mode against your local server
```bash
bun run dev                 # terminal 1 — Next dev server on :3000
bunx tauri dev              # terminal 2 — desktop window loads localhost:3000
```

## 5. What's where

| Path | Purpose |
|---|---|
| `capacitor.config.ts` | Capacitor app id, server.url, splash/push config |
| `scripts/build-native-shell.mjs` | Generates `dist/` bootstrap shell (both ecosystems) |
| `scripts/brand-android.py` | Branded splash + launcher background for Android |
| `scripts/brand-ios.py` | Branded App Store icon + launch splash + Info.plist strings for iOS |
| `android/` | Capacitor Android project (committed; build outputs ignored) |
| `ios/` | Capacitor iOS Xcode project, SPM plugins, branded assets (committed; build outputs ignored) |
| `src-tauri/` | Tauri Rust shell, icons, capabilities (build outputs ignored) |
| `.github/workflows/build-mobile.yml` | CI: Android APK + AAB, iOS unsigned IPA |
| `.github/workflows/build-desktop.yml` | CI: Windows / macOS Universal / Linux installers |

## 6. Releasing a new version

1. Deploy the server (`bun run build && bun run start` on your host) — native apps have no version of their own to ship otherwise.
2. Bump `version` in `package.json` and `src-tauri/tauri.conf.json`, `versionCode`/`versionName` in `android/app/build.gradle`, and `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` in `ios/App/App.xcodeproj/project.pbxproj`.
3. `git tag vX.Y.Z && git push --tags` — all three CI jobs build and attach artifacts to the release draft.
4. Sign the AAB with the Play upload key; upload to Play Console. Publish the desktop installers and iOS IPA from the GitHub release.
